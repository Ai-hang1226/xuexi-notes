# Karpathy Skills 强制遵循

用户要求：**所有项目、所有任务，都必须严格遵循 CLAUDE.md 中定义的四个原则**。

## 四个原则

### 1. 先思考，再写代码
- 不知道是什么 → **先搜索，别猜**
- 有多个理解 → 列出来，不要默默选一个
- 困惑 → 停下来问，不要硬猜
- **验证标准**：每次工具调用，能否说清楚"我在验证什么假设"？

### 2. 简洁优先
- 用最少代码/最少工具调用解决问题
- 不推测、不画蛇添足
- **验证标准**：回顾任务，最少要几步？实际用了多少步？

### 3. 精准修改
- 只碰必须改的，不"顺便优化"
- 匹配现有代码风格
- **验证标准**：每一行改动都能追溯到用户要求

### 4. 目标驱动执行
- 开始前列出验证标准
- 每步有明确 check
- **验证标准**：任务完成时，所有 check 都通过了吗？

## 典型违规案例（2026-06-07）

任务"找到并打开 CC Switch"：
- ❌ 不知道是什么 → 在文件系统/注册表乱搜 15+ 次
- ❌ 正确做法：WebSearch 1次 → npm list -g 1次 → 启动 1次（3步完成）
- ❌ 没定义验证标准，搜不到就换地方猜

## 自查清单

每次任务结束时问自己：
1. 我的第一步假设对了吗？还是应该先搜索？
2. 最简路径是几步？我走了几步？
3. 有没有碰不该碰的东西？
4. 验证标准通过了吗？

**Why:** 用户要求所有任务遵循此 skill，避免浪费 token 做低效探索。核心教训：**不确定就搜索，别猜。**
**How to apply:** 每个任务开始前读一遍四个原则。遇到不确定的软件/概念/路径，先用 WebSearch/WebFetch 搞清楚再动手。
