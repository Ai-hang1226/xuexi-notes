# 日常工作流

## 截图复盘与归档流程（2026-09-12 约定，优先于下方旧流程）

用户后续会发送做错或没把握的题目截图，并说明自己的思路。默认完成解答、分类整理、上传，再根据用户查看网站后的反馈修改，不必每题重复询问是否归档上传。若用户当次要求只讨论、暂不上传，以当次要求为准。

1. **核对题目**：保留完整题干、选项和必要图表，记录用户答案与原始思路；截图模糊或缺少关键条件时先核实，不猜题。不编造题目来源、标准答案或用户思路。
2. **优先站内方法**：先查当前对应模块的方法库，定位具体题型与知识点；不足时联网查证并结合独立推理，保留来源链接。已有方法不适用或有误时明确说明，不强套。
3. **针对思路复盘**：指出用户哪些判断正确、从哪一步开始偏离、为什么偏离，给出正确解法和下次可执行的提醒，避免仅用“粗心”概括。做对但没把握的题标记为“存疑题”，不算作错题；未核实的答案注明是推导结论或待核实。
4. **先对比旧笔记，再归档**：用户明确要求每次先对照已有方法和同类错题，判断共同错因与区别，关联具体章节或旧题；已有方法直接引用，确有新方法或必要辨析时才补充，避免重复堆放解析。
   - **言语真题必须同步归位页**：除错题本外，同步更新 `xingce/言语体系总览与真题归位.md` 的体系节点标记、归位表、逐题详解和成长地图，沿用该页“归属、真题重现、我的错、归到体系”的格式，关联错题本和方法章节。明确本站收录序号与原卷题号；检查侧边栏、方法库入口和首页题数文案，按需更新，避免只录入错题本而遗漏真题归位。
5. **格式与前七题一致**：以 `cuotiben/xingce-cuoti.md` 前七题的实际格式为准：标题“序号 年份地区卷别-言语-题型（题号）”；六个字段依次为“日期、来源、模块、错误类型、我的错误答案、正确答案”；正文依次为“题目回顾、我为什么错了、正确思路、知识点关联、下次注意”。题干按句编号，题干与选项放在同一引用块；解析直接展开，保持原有篇幅和写法，不自行增加折叠、表格或额外栏目。个人思路与错因放在“我为什么错了”，来源链接和旧题对比归入“知识点关联”。存疑题可按事实将“我的错误答案”改为“我的答案”，不标成错题、不虚构复习情况。
6. **上传验证**：检查内容与站内链接，运行构建，只提交本次相关文件，推送后核实部署和实际页面，返回具体笔记链接。不得将无关本地配置或其他未提交改动一并上传；上传或部署未成功时如实报告。
7. **按效果调整**：用户查看线上实际效果后提出修改，沿用原笔记修订并再次上传验证。先用真实题目跑通流程，不预先扩建栏目或批量重构网站。

## 每日速记流程

1. 在 VS Code 中打开 `每日速记.md`
2. 在分隔线 `---` 下方，新内容写最上面
3. 格式：`#标签 #标签 内容`
4. 保存后终端执行：
   ```
   git add -A
   git commit -m "今日速记：内容摘要"
   git push
   ```

## 笔记写作流程

1. 在对应模块目录下创建/编辑 `.md` 文件
2. 本地预览：`npm run docs:dev` → `http://localhost:5173`
3. 满意后：`git add -A` → `git commit -m "内容"` → `git push`
4. GitHub Actions 自动部署到 GitHub Pages

## 项目管理

- 所有项目统一放在 `C:\Users\Administrator\Projects\`
- VS Code 用多根工作区管理多个项目
- 每个项目是独立的 Git 仓库

## VS Code 快捷键

| 搜索文件 | `Ctrl+P` |
| 全局搜索 | `Ctrl+Shift+F` |
| 打开终端 | `Ctrl+`` |

**Why:** 用户没有编程背景，需要清晰的步骤指引。
**How to apply:** 每次给操作建议时尽量给出具体命令，不要只说"提交代码"而要说 `git add -A; git commit -m "..."; git push`。
